# CRM «Школа каратэ Николаевой Антонины»

CRM для школы каратэ с 4 филиалами (по образцу CRM «Поколение», без клиентского
приложения и СКУД — только админка для сотрудников).
Фирменные цвета: красный / чёрный / белый.

## Структура

- `server/` — бэкенд: Node.js (ES-модули) + Express + PostgreSQL (чистый SQL через `pg`, без ORM).
- `web/` — фронтенд: React + Vite + Tailwind, админка `/admin` (ставится как PWA на телефон).
- `deploy/` — файлы для сервера: служба systemd, конфиг nginx, скрипт автобэкапа.
- `УСТАНОВКА_НА_СЕРВЕР.md` — пошаговая инструкция развёртывания (Windows + WinSCP).
- `ИНСТРУКЦИЯ_ВЛАДЕЛЬЦА.md` — как пользоваться системой каждый день.

## Что умеет система

- **Сотрудники и роли**: добавление сотрудников (логин — email), готовые роли
  Владелец / Администратор / Тренер, свои роли с галочками прав, режим
  «только свои клиенты» для тренера, смена пароля себе и сотрудникам.
- **Филиалы**: создание, переименование, адреса, удаление (Настройки → Филиалы).
- **Дашборд**: сводка по всем филиалам с выбором филиала (действующие клиенты,
  абонементы, выручка месяца, долги).
- **Клиенты**: импорт базы из Excel/CSV — все колонки файла видны со счётчиком
  заполненности, раскладка по филиалам из колонки файла, сопоставление
  значений колонки «Ответственный» с сотрудниками школы, защита от потери
  колонок, повторный импорт без дубликатов (по телефону и ID прежней CRM)
  с возможностью дополнять уже заведённые карточки.
  Карточка: привязка к филиалу, тренерам и направлениям, ответственный
  сотрудник, статус «активный / неактивный» (переключается одной кнопкой),
  контакты ученика и родителя с кнопками «Позвонить / WhatsApp / Telegram»,
  пол, возраст, источник, дата появления в базе, история оплат и посещений,
  персональная скидка и баллы, реферальный код. В списке — фильтры по
  филиалу, тренеру, ответственному и статусу.
- **Абонементы**: каталог тарифов, у каждого филиала может быть своя цена;
  выдача клиенту: цена по тарифу − скидка − баллы, поле «Своя цена»
  (скидки к ней не применяются), выдача «в долг».
- **Оплаты и долги**: операции за период с фильтрами по способу
  (наличные / перевод / расчётный счёт / онлайн) и филиалу, сводка
  приход/возвраты/итог, возвраты и удаление операций, список должников.
- Тренеры со схемой зарплаты: процент от оплат ИЛИ оклад + процент
  (сам расчёт — на этапе 5).

## Запуск локально

```bash
# База: PostgreSQL. Проще всего docker:
cd server && docker compose up -d

cd server
cp .env.example .env        # при docker-варианте менять ничего не нужно
npm install
npm run migrate             # применяет src/schema.sql (безопасно запускать повторно)
npm run seed                # роли, настройки, 4 филиала, владелец admin@karate.ru / admin123
npm run dev                 # API на :4000

cd ../web
npm install
npm run dev                 # Vite на :5173
```

Админка: http://localhost:5173/admin (вход `admin@karate.ru` / `admin123`).

## Этапы разработки

1. ✅ Каркас: сервер, схема БД, авторизация, деплой.
2. ✅ Филиалы, клиенты, тарифы с ценами по филиалам, выдача абонементов
   («своя цена», в долг), оплаты и должники, дашборд по филиалам.
3. ✅ Расписание по филиалам (изменение одного занятия и серии), посещаемость
   (отмечают тренер и администратор), журнал записи (групповые и персональные).
4. ✅ Лояльность: рейтинг приглашений («пришли и оплатили»), ручная
   корректировка баллов с историей. Уведомления и онлайн-оплата ЮKassa
   исключены из проекта по решению заказчика.
5. ✅ Воронка продаж (заявки → этапы → конверсия в клиента с переносом
   «кто пригласил» и направления), задачи по клиентам и заявкам,
   расчёт зарплаты тренеров (процент / оклад + процент) с детализацией.
6. ✅ Ночной автобэкап БД (`deploy/backup.sh` + cron, хранение 14 дней)
   и `ИНСТРУКЦИЯ_ВЛАДЕЛЬЦА.md` — справочник по ежедневной работе.

## Примечания

- Иконки в `web/public/` — временные (буква «К» в фирменных цветах). Замените
  на настоящий логотип школы: `logo.png`, `icon-192.png`, `icon-512.png`,
  `apple-touch-icon.png`.
- Сид создаёт «Филиал №1…№4» — переименуйте их и укажите адреса в
  Настройках → Филиалы.
- Обнулить базу клиентов (после пробного импорта):
  `npm run reset-clients` — покажет, что будет удалено;
  `npm run reset-clients -- --yes` — удалит клиентов и их историю, сделав
  перед этим резервную копию базы. Филиалы, тарифы, расписание и сотрудники
  остаются; `--leads` заодно очищает воронку.
